Testing whether an emulation is correct

Define success first, then evaluate on held-out conditions and interventions. Similar-looking behaviour alone does not identify the internal mechanism.

Use more than one score

TargetQuestionExample evaluation
StructureDo cells, connections, and types correspond?Misses, false merges, type confusion, proofreading coverage.
DynamicsDo responses match on held-out inputs?Time-series prediction, latent state, stability, timescales.
Causal responseDoes the same intervention cause the same change?Stimulation, suppression, lesions, recovery.
Learning and memoryAre the individual's acquired abilities retained?Retention, relearning, forgetting, untrained controls.
Body and environmentDoes correspondence survive closed-loop interaction?Novel environments, sensory delays, changed body conditions.

This is the guide's proposed evaluation framework, not a consensus certification standard. It draws on functional fidelity and limitations of system identification.[1][2]

Practical validation starting points

ZAPBench benchmarks brain-wide activity prediction using recordings of over 70,000 neurons in a larval zebrafish. It measures activity prediction under recorded conditions, not complete structural recovery or memory transfer.[3]

The Brain Emulation Challenge uses synthetic ground truth to examine measurement and reconstruction choices. MICrONS supports biological structure–function comparisons. These resources address different questions and are complementary rather than interchangeable.[4][5]

A protocol for interpretable comparison

  1. Fix the target: specify individual, region, task, timescale, and functions to retain.
  2. Separate data: prevent leakage across neighbouring time windows; state whether stimulus, session, or animal is held out.
  3. Provide baselines: compare simple models, shuffled connectivity, and activity-only models under matched conditions.
  4. Reserve interventions: keep evaluation stimulation, suppression, and lesion conditions out of optimization.
  5. Report uncertainty: include trial counts, animal variation, measurement error, random seeds, and confidence intervals.
  6. Preserve failures: publish failing conditions, extra training, computational cost, and data versions.

This is a reproducibility-oriented design proposal. It does not supply a score threshold that certifies “successful uploading.”

Failures also move the research forward

If a connectivity-only model fails on a particular intervention, the failure can identify missing information. Add receptor properties, release probability, adaptation, or neuromodulation in controlled steps, measuring the improvement each brings. Establishing which measurements are necessary is a concrete contribution toward WBE.
